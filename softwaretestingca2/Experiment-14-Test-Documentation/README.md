# Experiment 14: Test Plans, Test Suites, and Test Summary Reports

## Objective
Prepare the three key test documentation artifacts used during a software testing project.

## Files
- `test_plan.md`: scope, objectives, features, entry/exit criteria, roles, schedule, and risks.
- `test_suite.csv`: related login test cases in spreadsheet-friendly CSV format.
- `test_summary_report.md`: execution metrics, defects, observations, recommendation, and sign-off.

## Steps
1. Review the test plan before starting testing.
2. Use the test suite to execute and record each test case.
3. Compare actual results with expected results.
4. Log defects for failed cases.
5. Complete the summary report after execution.
6. Make a release recommendation based on exit criteria and open defects.

## Open the CSV
Open `test_suite.csv` in Microsoft Excel, LibreOffice Calc, or a text editor.

## Key differences
- **Test Plan:** what, why, how, who, and when to test.
- **Test Suite:** a collection of related test cases.
- **Test Summary Report:** what happened during testing and whether the product is ready.

The sample report data follows the lab-manual example. Replace it with actual execution results for a real project.
